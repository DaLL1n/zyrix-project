# Схема таблицы `public.profiles`

| Название поля            | Тип данных    | Что хранит                                                                             | Где и когда заполняется                                                                         | Нужно ли передавать с фронтенда?                                                                |
| :----------------------- | :------------ | :------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------- |
| **`id`**                 | `uuid`        | Уникальный ID профиля. Связан с `auth.users(id)`.                                      | Автоматически БД при регистрации (триггер).                                                     | **Нет.** Формируется само.                                                                      |
| **`public_uid`**         | `bigint`      | Красивый порядковый ID для интерфейса (напр. _Участник №1024_), чтобы не светить UUID. | Увеличивается автоматически БД (+1 к предыдущему) при регистрации.                              | **Нет.** Формируется само.                                                                      |
| **`email`**              | `text`        | Почта для удобного поиска и связи.                                                     | На этапе регистрации из введенных данных через триггер.                                         | **Да** (при регистрации). Отправляем в `supabase.auth.signUp({ email })`.                       |
| **`name`**               | `text`        | Реальное имя (для KYC или приветствия).                                                | При регистрации или позже на странице «Настройки / Профиль».                                    | **Да**. Отправляем в `options.data.name` (при рег-ии) или апдейтим позже.                       |
| **`surname`**            | `text`        | Реальная фамилия.                                                                      | Аналогично полю `name`.                                                                         | **Да**. Отправляем в `options.data.surname` или апдейтим позже.                                 |
| **`account_name`**       | `text`        | Уникальный никнейм (`@CryptoNinja`).                                                   | При регистрации генерируется временный (`user_93j2a`). В настройках юзер может сменить на свой. | **Да** (только при смене). Когда юзер редактирует профиль в "Настройках".                       |
| **`phone_number`**       | `text`        | Номер телефона (для 2FA или связи).                                                    | В личном кабинете на странице "Настройки / Безопасность".                                       | **Да.** Если юзер хочет его привязать.                                                          |
| **`referral_code`**      | `text`        | Личный уникальный код юзера (для приглашений).                                         | Автоматически БД (триггером) при регистрации (напр. `MFPBAv`).                                  | **Нет.** Это код, который фронтенд просто _показывает_ пользователю.                            |
| **`referred_by`**        | `uuid`        | ID того человека, чей код мы ввели при регистрации.                                    | Автоматически триггером, если с фронтенда пришел `invitation_code`.                             | **Да** (только код при регистрации). Отправляем `invitation_code` в `options.data`.             |
| **`avatar_url`**         | `text`        | Ссылка на аватарку из бакета Storage.                                                  | В личном кабинете, когда юзер загружает фото профиля.                                           | **Да.** Сначала грузите файл в Storage, потом сохраняете ссылку сюда.                           |
| **`identification_uid`** | `text`        | ID сессии стороннего KYC-провайдера (если будет интеграция).                           | Во время прохождения верификации личности на странице KYC.                                      | Зависит от KYC-апи (может фронтенд, может бэкенд-вебхук).                                       |
| **`verification_level`** | `enum`        | Уровень доступа (`unverified`, `basic`, `advanced`). Влияет на лимиты.                 | По умолчанию `unverified`. Меняется только сервером после проверки документов.                  | **Строго Нет.** Это делает только защищенный бэкенд/админ. Фронтенд только _читает_ это для UI. |
| **`metadata`**           | `jsonb`       | Доп. неструктурированные данные (тема, язык, мелкие настройки интерфейса).             | В любой момент, когда нужно сохранить юзерские предпочтения.                                    | **Да** (если решите это использовать).                                                          |
| **`created_at`**         | `timestamptz` | Дата и время регистрации.                                                              | Автоматически БД.                                                                               | **Нет.**                                                                                        |
| **`updated_at`**         | `timestamptz` | Дата и время последнего изменения профиля.                                             | Автоматически БД (триггером при любом UPDATE).                                                  | **Нет.**                                                                                        |
